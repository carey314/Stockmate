## 一、模板（空白版，拿去填新画像）

填的时候有个原则：**不要写"他需要进销存"**，写"他今天有哪件事没干成"。前者是我们的语言，后者才是他的。

| 维度 | 要回答的问题 | 填写要点 |
|---|---|---|
| **Who** 他是谁 | 年龄/生意类型/一天卖多少/几个人干 | 别只写老板，**员工和老板娘也是用户**，权限需求完全不同 |
| **What** 他要完成什么 | 他嘴里的任务原话是什么 | ❌"管理库存" ✅"我想知道今天到底赚没赚"、"月底跟老王把账对上" |
| **When** 什么时候用 | 一天中的哪几个时刻 | 这决定交互形态：**收摊后累得不想打字 → 语音；进货时手上拿着货 → 拍照** |
| **Where** 在什么环境 | 摊位/货车/柜台/家里 | 决定了：单手操作？戴手套？光线？有没有网？吵不吵（影响语音）？ |
| **Why** 为什么用 / **为什么不用** | 痛到什么程度 + 阻力是什么 | **"为什么不用"比"为什么用"重要**——他大概率已经下过一个同类 App 没坚持 |
| **How** 怎么用 | 他期待的操作路径 | 跟我们设计的路径对比，差距就是流失点 |
| ⭐ **What breaks** 什么时候会放弃 | 哪一步他会关掉再也不打开 | 这一栏最值钱，其余五栏都是为它服务的 |

## 二、三个填好的样例

### 画像 A：馄饨摊王姐（52 岁，早市）

| | |
|---|---|
| **Who** | 一个人守摊，卖 6 种馄饨（袋装/散称）+ 饮料。手机字调最大档 |
| **What** | "今天卖了多少？够不够本？"、"面粉还剩多少，明天要不要进" |
| **When** | 早上 5 点进货、白天间歇、**收摊后累瘫时记一天的账** |
| **Where** | 露天摊位，手上油、戴手套、光线强、周围吵 |
| **Why 用** | 现在靠脑子记，月底算不清；进多了烂掉，进少了不够卖 |
| **Why 不用** | 下过一个进销存 App，"录一个商品要填十几个格子"，第二天就卸了 |
| **How** | 想对着手机说一句"今天卖了大概800，收现金650，老王赊了3袋" |
| ⭐ **What breaks** | **注册完看到一屏零 + 让她建商品档案** —— 她会当场放弃 |

### 画像 B：酒水批发老徐（45 岁，批发部）

| | |
|---|---|
| **Who** | 200+ 商品，整箱/单瓶双规格，30 多个餐馆客户长期挂账 |
| **What** | "月底把账对平"、"谁欠我最多"、"送货现场把单开了" |
| **When** | 白天送货途中开单、**月底集中对账收款**（最痛的时刻） |
| **Where** | 货车驾驶室、客户后厨门口，站着单手操作 |
| **Why 用** | 挂账全靠微信聊天记录翻，对账时跟客户吵过架 |
| **Why 不用** | 用过智慧记，"收费背刺"（限单据数量）让他很反感 |
| **How** | 扫码加货 → 自动带这个客户谈好的价 → 生成对账单发微信 |
| ⭐ **What breaks** | **改价麻烦**（每个客户价不同，要是每次都得手动改就崩溃）；**对账单不能直接发微信** |

### 画像 C：水果店刘哥 + 员工小妹

| | |
|---|---|
| **Who** | 刘哥老板，小妹收银。全按斤卖（2.35 斤这种） |
| **What** | 刘哥："这个月烂掉多少钱"；小妹："快点开单收钱" |
| **When** | 刘哥晚上看账，小妹全天开单 |
| **Where** | 店里柜台，小妹手忙脚乱时开单 |
| **Why 用** | 损耗是利润杀手，但从来算不清烂了多少 |
| **Why 不用** | 怕员工看到进货价和利润 |
| **How** | 小妹只管开单报损；刘哥独享报表 |
| ⭐ **What breaks** | **小数量输入不方便**（2.35 斤）；**员工能看到利润** → 刘哥立刻弃用 |

## 四、优化建议（按投入产出排序）

### 🥇 第一优先：开机 30 秒引导（这是生死线）

现状：注册 → 一屏零 → 自己摸索。承诺是"30 秒配成你这行"，但**没有那 30 秒**。

建议流程（3 屏，可跳过）：
1. **"你是做什么生意的？"** 一个输入框 + 几个常见选项气泡（水果店/酒水批发/餐饮/便利店/服装…）
2. AI 现场生成这行该有的字段和规格 → **"这是给你配的，可以改"**（我们已有 `/ai/generate-fields`）
3. **"要不要现在录几个常卖的货？"** → 调 `/ai/generate-products` 出草案，勾选入库；或"先跳过，用语音边卖边记"

关键：**第 3 步结束时，他的库里已经有东西了**，首页不再是一屏零。

### 🥈 第二优先：口述页显示"今天还剩 N 次"

半小时的事。接口已经返回 `today.coreUsed/coreLimit`，只差 UI。不显示的话，用户撞墙那一下会很突然。

### 🥉 第三优先：开单成功后直接"发给客户"

现在是：开单成功 → 回列表 → 点进详情 → 分享。老徐站在客户后厨门口，这三步太多。
建议：开单成功的提示条上直接给一个"发给客户"按钮。

### 其余
- 员工首页把"今日毛利"换成"今天开了几单"（他关心的和老板不一样）
- 配方 BOM 在商品详情页给个显式入口

## 五、宣传角度

### 核心洞察

进销存这个需求**已经被竞品教育过了**（智慧记 300 万商户）。所以不用再解释"为什么要记账"。

但那 300 万里有大量是**下了没用起来**——因为录一笔要点十几下。

**所以我们不该卖"功能更多的进销存"，该卖"这次你能坚持下来的进销存"。**

### 主角度：对准他失败过的那次

> **"以前记不下去，不是你懒，是记一笔要点十几下。"**
>
> 现在：收摊了对着手机说一句"今天卖了800，老王赊了3袋"，账就记好了。

为什么这个角度强：
- 它**承认了用户的失败经验**（大部分小店主都下过、放弃过），而不是指责他
- 它把矛头指向"操作成本"这个真问题，不是空喊"智能"
- 它可验证——用户下载后 30 秒内就能确认真假

### 三个辅助角度（按人群切）

| 人群 | 一句话 | 打的是 |
|---|---|---|
| 批发/挂账多 | **"月底不用再翻微信找账了"** | 对账吵架的痛 |
| 刚起步的小店 | **"不用学，说出你做什么生意，AI 给你配好"** | 学习成本 |
| 被收费坑过的 | **"数据随时全量导出，永远免费"** | 竞品收费背刺史 |

### 短视频脚本（第一条，抖音/快手）

画面感最强的就是那个动作本身：

```
[0-3秒] 收摊画面，手上还沾着面粉，人很累
        字幕：以前每天这时候最烦
[3-8秒] 拿出手机对着说："今天卖了八百多，收现金六百五，老王赊了三袋"
[8-12秒] 屏幕特写：AI 自动拆成 卖出/收款/挂账 三条，金额都在
        字幕：说一句话，账就记完了
[12-15秒] 首页毛利数字
        字幕：今天赚了多少，一眼就知道
```

**不要配旁白解释"这是AI进销存软件"**。让那个"说一句话→账自动记好"的动作自己说话。

### 不能说的（会翻车）

代码核对过，这几条我们**没有**，宣传里绝不能出现：
- ❌ "离线也能开单"（只有选货弹窗/客户/供应商有缓存，提交必须联网）
- ❌ "推送提醒催你收款"（通知中心是打开 App 才聚合，零推送）
- ❌ "拍照识别"（严格说是从相册选图，虽然现在也支持拍照了，但表述要准）
- ❌ "微信/华为登录"（UI 未渲染，只有 Apple 登录）
- ❌ 泛泛的"最好用的进销存"（无法验证，等于没说）

### 渠道建议

- **抖音/快手**优先：目标人群在这里，且"说话记账"的画面天生适合短视频
- **同行微信群**：批发商圈子传播力强，老徐这类用户会互相推荐
- **暂时别投 ASO 硬广**：预算有限、转化差，不如把钱花在做几条好视频上
